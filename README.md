## CRUD-операции

Наша СУБД поддерживает полный цикл работы с записями в таблицах (создание, чтение, обновление, удаление). Данные каждой таблицы изолированно хранятся в формате JSON в директории `data/`.

### Системные требования к данным
*   **Автоматический ID:** При добавлении записи (`insert`) указывать значение ID не нужно. СУБД автоматически генерирует уникальный ID на основе максимального существующего идентификатора в таблице (метод `max(IDs) + 1`).
*   **Обязательность полей:** Все объявленные при создании таблицы столбцы являются строго обязательными для заполнения.
*   **Строковые значения:** Все строки (тип `str`) в условиях фильтрации `WHERE` и `SET` обязательно должны быть обёрнуты в кавычки (например, `"Ivan"` или `'Alex'`).

---

### Описание команд и синтаксис

1.  **`insert <имя_таблицы> <значение1> <значение2> ...`**
    Добавляет новую строку в таблицу. Значения передаются через пробел в порядке объявления столбцов (исключая ID).
    *Пример:* `insert users "Ivan" 25 True`

2.  **`select <имя_таблицы> [условие]`**
    Выводит содержимое таблицы в красивом табличном формате с помощью библиотеки `PrettyTable`. Если условие не указано, выводит все записи.
    *Пример:* `select users` или `select users age = 25`

3.  **`update <имя_таблицы> set <поле = значение> where <поле = значение>`**
    Обновляет указанные поля в записях, соответствующих критерию фильтрации.
    *Пример:* `update users set is_active = False where age = 25`

4.  **`delete <имя_таблицы> where <поле = значение>`**
    Удаляет из таблицы записи, которые подходят под условия фильтра.
    *Пример:* `delete users where age = 25`

---

## Продвинутые механизмы и оптимизация

В текущей версии СУБД реализована отказоустойчивая архитектура на базе декораторов и встроенная система оптимизации запросов.

### 🛡️ Обработка ошибок и защита данных (Декораторы)
Для централизованного управления стабильностью приложения используется модуль `src/primitive_db/decorators.py`:
*   **`@handle_db_errors`**: Автоматически оборачивает функции ядра в блоки `try...except`, изолируя сбои `KeyError` (обращение к несуществующим таблицам), `ValueError` (несовместимость типов данных) и `FileNotFoundError`. Программа выводит понятное предупреждение в консоль и продолжает работу без аварийного завершения.
*   **`@confirm_action("<название>")`**: Фабрика декораторов для защиты от случайного удаления данных. Применяется к операциям `drop_table` и `delete`. Перед выполнением запрашивает интерактивное подтверждение `[y/n]`. При вводе любого символа кроме `y` операция безопасно отменяется.
*   **`@log_time`**: Профилирует СУБД, замеряя время выполнения операций с диском (`insert`, `select`) с помощью высокоточных монотонных часов (`time.monotonic()`).

### ⚡ Оптимизация (Кэширование через замыкания)
Для минимизации обращений к жесткому диску при чтении данных реализован модуль `src/primitive_db/cache.py`:
*   Механизм **`create_cacher`** использует замыкание (closure) для долгосрочного хранения кэша в памяти сессии.
*   При повторном вызове идентичной команды `select` данные мгновенно считываются из оперативной памяти без повторного парсинга физических JSON-файлов.
*   Кэш автоматически сбрасывается в начале любой изменяющей транзакции (`insert`, `update`, `delete`, `create_table`, `drop_table`), гарантируя постоянную актуальность выдачи.
